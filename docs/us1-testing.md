# วิธีติดตั้งและตรวจรับ US-1

## เตรียมก่อนทดสอบ

1. Supabase → SQL Editor → New query → คัดลอกเนื้อหาทั้งไฟล์ `supabase/migrations/20261114000100_us1_profiles.sql` → Run เพียงครั้งเดียว ไฟล์นี้สร้าง profiles, RLS (กฎจำกัดการอ่านข้อมูล) และ trigger (คำสั่งที่ทำงานอัตโนมัติเมื่อสมัคร) ไม่ต้องรันกับฐานข้อมูลซ้ำ
2. Authentication → Sign In / Providers → Email → ปิด Confirm email → Save ตามการตั้งค่า workshop เพื่อให้สมัครแล้วล็อกอินทันที
3. ใช้ค่าเดิม `NEXT_PUBLIC_SUPABASE_URL` และ `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` ใน `.env.local` ไม่มีตัวแปรใหม่และไม่ใช้ secret key
4. เปิด Terminal ในโฟลเดอร์โปรเจกต์ รัน `npm run dev` แล้วเปิด `http://localhost:3000/login`

## ตรวจสิทธิ์ด้วยสองบัญชี

สมัคร A ในหน้าต่างปกติ และ B ในหน้าต่างไม่ระบุตัวตน แต่ละหน้าต่างต้องแสดงชื่อตนเอง เปิด Table Editor เพียงเพื่อจด UUID ของ A และ B (ไม่ใช้ผลจาก Table Editor เป็นหลักฐาน RLS เพราะผู้ดูแลข้าม RLS ได้)

ตรวจผ่าน Console ของเบราว์เซอร์ที่ล็อกอินเป็น A โดยใช้ publishable key ของโปรเจกต์และ access token ของ A เท่านั้น เรียก REST `GET /rest/v1/profiles?select=user_id,display_name` พร้อม header `apikey: <publishable key>` และ `Authorization: Bearer <access token ของ A>` ต้องได้เฉพาะ A เมื่อเพิ่ม `&user_id=eq.<UUID ของ B>` ต้องได้ `[]` ทำกลับกันด้วย B ต้องไม่เห็น A และเมื่อไม่ส่ง token ผู้ใช้ต้องอ่าน profiles ไม่ได้ ห้ามเผยแพร่ token หรือวางในแชท

ลอง PATCH/POST/DELETE ผ่าน REST ด้วย token ของ A ต้องถูกปฏิเสธ เพราะรอบ US-1 ให้สิทธิ์ผู้ใช้อ่านตนเองเท่านั้น ชื่อและอีเมลเพิ่มจาก trigger การสมัคร ไม่เปิดเขียนตรง ข้อกำหนดอ่านข้อมูลเพื่อนร่วมทีมจะเพิ่มใน US-2

## ขอบเขตการตรวจ

US-1 ยังไม่มีระบบสร้างทีมและงาน หน้า /team เป็นหน้ารับหลังล็อกอิน ส่วน /tasks และ /my เป็นหน้ารอพัฒนาที่ป้องกันการเข้าถึงแล้ว การเลือกผู้รับงานเฉพาะสมาชิกทีมอยู่ใน US-3

คำสั่งตรวจโค้ดคือ `npm run lint` และ `npm run build` โปรเจกต์ยังไม่มีคำสั่ง test อัตโนมัติ การตรวจจริงกับ Auth และ RLS ต้องทำหลังรัน SQL โดยใช้รายการข้างต้น อ่านการเปลี่ยนแปลงและ commit ก่อนเริ่ม US-2
