# ติดตั้งและทดสอบ US-2–US-4

## ติดตั้ง

ต้องทำ US-1 และรัน `20261114000100_us1_profiles.sql` แล้ว ไม่ต้องรันไฟล์ US-1 ซ้ำ

เปิด Supabase → SQL Editor → New query แล้ววางเนื้อหาไฟล์ต่อไปนี้ทั้งไฟล์ กด Run ทีละไฟล์ตามลำดับ:

1. `supabase/migrations/20261114000200_us2_teams.sql`
2. `supabase/migrations/20261114000300_us3_us4_tasks.sql`

ไฟล์เหล่านี้ใช้รันครั้งเดียว ไม่ต้องเพิ่มตัวแปรใน `.env.local` ใช้ URL และ publishable key เดิม ไม่มี secret key จากนั้นเปิด Terminal ในโฟลเดอร์โปรเจกต์ รัน `npm run dev` หากยังไม่ได้เปิด แล้วไป `http://localhost:3000/team` และโหลดหน้าใหม่

| B กรอกรหัสผิด เช่น !!!!!! | “ไม่พบทีมจากรหัสนี้” | AC-2.3 |

| A และ B โหลด /team ใหม่ | ไม่เห็นฟอร์มสร้าง/เข้าร่วมทีม | AC-2.4 |

## ตรวจการส่งคำขอข้ามหน้าจอ

การซ่อนปุ่มไม่ใช่หลักฐานเรื่องสิทธิ์ ต้องตรวจฐานข้อมูลด้วย ด้านล่างใช้ SQL Editor ของเจ้าของโปรเจกต์จำลองบทบาทผู้ใช้จริง โดยตั้ง `role authenticated` ให้ RLS (กฎจำกัดข้อมูลแต่ละแถว) ทำงาน ห้ามตรวจด้วย SELECT แบบผู้ดูแลธรรมดา เพราะผู้ดูแลข้าม RLS ได้

จด UUID บัญชี A/B/C จาก Authentication → Users, id ทีมจาก Table Editor → teams และ id งานจาก tasks แทน `<...>` ด้วยค่าจริงทุกแห่ง รันตัวอย่างแต่ละกรณีเป็น query แยกกัน ก่อนเริ่มกรณีถัดไปกด Run คำสั่ง `rollback;` หากกรณีก่อนเกิด error เพื่อออกจากรายการที่ถูกยกเลิก

แม่แบบสำหรับกรณีที่คาดว่าสำเร็จ (ROLLBACK ทำให้ไม่เปลี่ยนข้อมูลจริง):

```sql
begin;
set local role authenticated;
select set_config('request.jwt.claim.sub', '<UUID ของ C>', true);
select * from public.teams where id = '<id ทีม 1>';
select * from public.team_members where team_id = '<id ทีม 1>';
select * from public.profiles where user_id in ('<UUID ของ A>', '<UUID ของ B>');
select * from public.tasks where team_id = '<id ทีม 1>';
rollback;
```

ทั้งสี่ SELECT ต้องได้ 0 แถว (AC-2.6, AC-3.7) ลองเปลี่ยน C เป็น B ต้องเห็นทีม 1, สมาชิก A/B และงานของทีม 1

ใช้แม่แบบ `begin; set local role authenticated; select set_config(...); <คำสั่งตรวจ>; rollback;` สำหรับแต่ละกรณีต่อไปนี้:

| ผู้ใช้จำลอง | คำสั่งตรวจ | ผลที่ต้องได้ |
|---|---|---|
| B ที่มีทีมแล้ว | `select public.create_team('ทีมซ้ำ');` หรือ `select public.join_team('รหัสทีม1');` | error ALREADY_IN_TEAM; หน้าจอแปลเป็น “คุณมีทีมอยู่แล้ว” (AC-2.4) |
| B | `insert into public.tasks(team_id,title,assignee_id,created_by) values ('<ทีม1>','แอบสร้าง','<B>','<B>');` | ถูก RLS ปฏิเสธ (AC-3.3) |
| A | `insert into public.tasks(team_id,title,assignee_id,created_by) values ('<ทีม1>','ข้ามทีม','<C>','<A>');` | ถูก foreign key (กฎอ้างอิงสมาชิกทีม) ปฏิเสธ (AC-3.4) |
| B | `update public.tasks set title='แอบแก้' where id='<งานของ B>';` | error ONLY_STATUS_ALLOWED (AC-4.4) |
| B | เปลี่ยนคำสั่งข้างบนเป็น `description='แอบแก้'`, `due_date='2030-01-01'`, `assignee_id='<A>'` ทีละ query | ทุกกรณีถูกปฏิเสธ (AC-4.4) |
| B | `update public.tasks set status='done' where id='<งานของ A>' returning id;` | ได้ 0 แถว งานไม่เปลี่ยน (AC-4.3) |
| C | `update public.tasks set status='done' where id='<งานของ B>' returning id;` | ได้ 0 แถว งานไม่เปลี่ยน |
| B | `update public.tasks set status='doing' where id='<งานของ B>' returning id;` | ได้ 1 แถว แต่ ROLLBACK ย้อนกลับ (AC-4.1) |
| B | `update public.tasks set status='unknown' where id='<งานของ B>';` | ถูก CHECK ปฏิเสธ |

ลองใช้ publishable key ผ่าน REST ด้วย token ของผู้ใช้จริงเช่นเดียวกันต้องได้สิทธิ์ตรงกัน และคำขอที่ไม่มี token ต้องอ่านตารางแอปไม่ได้ ห้ามใส่ secret key หรือเผยแพร่ token

## ขอบเขตการตรวจที่ทำระหว่างพัฒนา

รัน `npm run lint` และ `npm run build` โปรเจกต์ไม่มีคำสั่ง test ใน package.json ทดสอบ SQL ทั้งสามไฟล์ด้วย PGlite (PostgreSQL ในเครื่องแบบชั่วคราว) โดยจำลอง auth.users, auth.uid(), anon และ authenticated แยกจากฐานข้อมูล Supabase จริง ครอบคลุมสร้าง/เข้าทีม, คนละทีมอ่านกันไม่ได้, หนึ่งคนมีทีมเดียว, สมาชิกสร้างงานไม่ได้, FK ป้องกันมอบหมายข้ามทีม, ผู้รับแก้ได้เฉพาะสถานะ และปิดสิทธิ์ลบ/anon ผ่านแล้ว

ผลจำลองยังไม่ยืนยันการเชื่อมต่อ Auth และ cookie จริง หรือคำขอพร้อมกันบน Supabase ต้องตรวจรายการด้านบนหลังติดตั้ง SQL การสร้างและเข้าทีมล็อกแถว profiles เดียวกันและมี primary key ป้องกัน membership ซ้ำ อ่านการเปลี่ยนแปลงและ commit ก่อนเริ่ม US-5
